# 06. 인증 및 사용자 권한

대시보드는 **Google OAuth 로그인**으로 사용자를 인증하고,
**BigQuery 테이블(`DASHBOARD.AUTH_USERS`)** 기반으로 사업군별 접근을 제어한다.

## 동작 흐름

```
URL 접속
  → 앱에서 Google 로그인 화면 표시
    → 로그인 → 이메일 확인
      → AUTH_USERS 테이블 조회
        ├─ 등록됨 → 권한 있는 사업군만 사이드바에 표시
        └─ 미등록 → "접근 권한 없음" 화면
```

## 권한 테이블: `DASHBOARD.AUTH_USERS`

| 컬럼 | 타입 | 설명 |
|------|------|------|
| `email` | STRING | 사용자 Google 이메일 |
| `bsark` | STRING | 접근 가능한 사업군 코드 (`all`이면 전체) |
| `role` | STRING | `user`(조회) 또는 `admin`(사용자 관리 가능) |
| `name` | STRING | 표시 이름 |
| `created_at` | TIMESTAMP | 등록 시각 |

- 앱 최초 실행 시 자동 생성되며, 기본 관리자(`pjy011004@gmail.com`, `all`/`admin`)가 삽입됨
- 캐시 60초 → 추가/삭제 후 최대 1분 뒤 반영

## 권한 조합

| bsark | role | 볼 수 있는 사업군 | 사용자 관리 탭 |
|-------|------|------------------|--------------|
| `all` | `admin` | 전부 | O (슈퍼 관리자) |
| `all` | `user` | 전부 | X |
| `3310` | `admin` | 자격증만 | O |
| `3310` | `user` | 자격증만 | X |

> 한 사람이 여러 사업군을 봐야 하면 **같은 이메일로 사업군별 행을 각각 추가**한다.

### 사업군 코드

| 코드 | 사업군 |
|------|--------|
| `3310` | 자격증 |
| `3080` | 잡 |
| `3340` | 한국사 |
| `all` | 전체 (관리자) |

## 사용자 추가/삭제 (빌드 불필요)

관리자(`role=admin`)로 로그인하면 상단에 **"사용자 관리"** 탭이 나타난다.

1. 이메일 입력
2. 사업군 선택 (`all` 또는 특정 코드)
3. 역할 선택 (`user` / `admin`)
4. 이름 입력 → **추가**

즉시 BQ 테이블에 반영되며 재배포가 필요 없다.

### 추천 운영 구조

```
슈퍼 관리자   → all + admin      (전체 관리)
사업군 팀장   → 3310 + admin     (자기 팀원 직접 관리)
사업군 팀원   → 3310 + user      (조회만)
```

## OAuth 설정 (GCP 콘솔)

### OAuth 클라이언트

- 위치: API 및 서비스 > 사용자 인증 정보 > OAuth 클라이언트 ID (웹 애플리케이션)
- **승인된 JavaScript 원본:** `https://sales-dashboard-397756181081.asia-northeast3.run.app`
- **승인된 리디렉션 URI:** `https://sales-dashboard-397756181081.asia-northeast3.run.app`
- Client ID / Secret → Cloud Run 환경변수(`OAUTH_CLIENT_ID`, `OAUTH_CLIENT_SECRET`)로 전달

### OAuth 동의 화면

- **테스트 모드:** 등록한 "테스트 사용자"만 로그인 가능 (최대 100명)
- **프로덕션(앱 게시):** 누구나 Google 로그인 가능 (권한 체크는 앱에서 하므로 안전)
  - 사내 전체 배포 시 "앱 게시" 눌러 프로덕션으로 전환

## 환경변수

| 변수 | 값 |
|------|-----|
| `OAUTH_CLIENT_ID` | OAuth 클라이언트 ID |
| `OAUTH_CLIENT_SECRET` | OAuth 클라이언트 시크릿 |
| `CLOUD_RUN_URL` | 서비스 URL (리디렉션 대상) |

> 환경변수가 없으면 앱은 인증 없이 전체 접근을 허용한다 (로컬 개발용).
> 운영 환경에서는 반드시 3개를 모두 설정해야 로그인이 강제된다.

## 트러블슈팅

| 증상 | 원인 | 해결 |
|------|------|------|
| `401 invalid_client` / `OAuth client was not found` | 클라이언트 ID 오타 또는 클라이언트 비정상 | Client ID 전체 재확인, 필요 시 클라이언트 삭제 후 재생성 |
| 로그인 후 `redirect_uri_mismatch` | 리디렉션 URI 미등록 | 콘솔에 서비스 URL을 리디렉션 URI로 추가 |
| 로그인 화면 안 뜨고 바로 진입 | 환경변수 미설정 | `OAUTH_CLIENT_ID/SECRET` 배포 시 전달 |
| 테스트 사용자인데 로그인 거부 | 동의 화면 테스트 사용자 미등록 | 동의 화면에 이메일 추가 또는 앱 게시 |
| 등록했는데 사업군 안 보임 | 캐시(60초) | 잠시 후 새로고침 |

## 사업군 추가 시 (코드 수정 필요)

새 사업군(예: 공무원 `3350`)을 추가하려면 `app.py`의 `BSARK_OPTIONS`에 한 줄 추가 후 재빌드:

```python
BSARK_OPTIONS = {
    "3310": "자격증",
    "3080": "잡",
    "3340": "한국사",
    "3350": "공무원",   # 추가
}
```

> 사용자 추가는 빌드 불필요하지만, **사업군 목록 자체를 늘리는 건 코드 수정 + 재배포**가 필요하다.
