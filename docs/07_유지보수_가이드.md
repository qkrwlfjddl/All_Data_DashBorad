## 기본 구조 이해

```
[로컬/Cloud Shell]          [GCP]
  app.py  ───빌드───→  Docker 이미지  ───배포───→  Cloud Run 서비스
                                                    ↓
                                              사용자 접속
                                                    ↓
                                              BigQuery (데이터/권한)
                                              Vertex AI (AI 리포트)
                                              네이버 API (검색 트렌드)
```

- **코드 변경** → 빌드 + 배포해야 반영
- **데이터 변경** (사용자 추가, KPI 업로드, 프리셋 저장) → BigQuery에 직접 반영, 빌드 불필요

## 수정 후 배포 흐름 (공통)

코드 수정이 필요한 모든 케이스에 공통으로 적용되는 절차.

### 1단계: Cloud Shell 접속 및 환경 설정

```bash
# Cloud Shell 열기 (console.cloud.google.com 상단 터미널 아이콘)
export PROJECT_ID="ga4-bigquery-431807"
cd ~/sales-dashboard
```

### 2단계: 코드 수정

```bash
# 파일 편집 (nano 또는 vim)
nano app.py
```

> 로컬(VS Code 등)에서 수정 → Cloud Shell에 업로드해도 됨.
> Cloud Shell 좌측 패널에서 파일 업로드 가능.

### 3단계: 빌드

```bash
gcloud builds submit \
  --tag asia-northeast3-docker.pkg.dev/$PROJECT_ID/sales-dashboard/app:latest
```

- 소요시간: 약 2~3분
- 빌드 실패 시: `gcloud builds log <빌드ID>` 로 로그 확인

### 4단계: 배포

```bash
gcloud run deploy sales-dashboard \
  --image=asia-northeast3-docker.pkg.dev/$PROJECT_ID/sales-dashboard/app:latest \
  --region=asia-northeast3 \
  --platform=managed
```

- 소요시간: 약 30초
- 배포 후 URL 접속하면 바로 새 버전 반영
- **기존 환경변수/서비스 계정은 자동으로 유지됨** (다시 안 넣어도 됨)

### 5단계: 확인

브라우저에서 접속하여 변경사항 확인:
```
https://sales-dashboard-397756181081.asia-northeast3.run.app
```

### A. 사용자 추가/삭제

**빌드 필요: ❌ 없음**

대시보드에 로그인 후 "사용자 관리" 탭에서 추가/삭제하면 끝.
BigQuery `DASHBOARD.AUTH_USERS` 테이블에 바로 반영된다.

| 항목 | 방법 |
|------|------|
| 사람 추가 | 사용자 관리 탭 → 이메일 + 사업군 + 역할 입력 → 추가 |
| 사람 삭제 | 사용자 관리 탭 → 해당 행 삭제 |
| 여러 사업군 접근 | 같은 이메일로 사업군별 각각 추가 |

**다른 사업군 영향:** 없음. 해당 사용자만 영향.

**주의:** OAuth 동의 화면이 "테스트 모드"면 새 사용자를 GCP 콘솔 > OAuth 동의 화면 > 테스트 사용자에도 등록해야 함. "앱 게시"(프로덕션)로 바꾸면 이 제한 없음.

### B. 기존 화면 수정

**빌드 필요: ✅**

예시: 차트 색상 변경, 컬럼 추가, 텍스트 수정, 버그 수정 등

#### 수정 위치

| 변경 내용 | 수정 파일 | 찾는 방법 |
|-----------|-----------|-----------|
| 연간 탭 관련 | `app.py` → `render_annual_tab()` | 함수명으로 검색 |
| 일간 탭 | `app.py` → `render_daily_tab()` | |
| 판매상품 탭 | `app.py` → `render_product_tab()` | |
| 이벤트 탭 | `app.py` → `render_event_tab()` | |
| 교재 순위 탭 | `app.py` → `render_book_tab()` | |
| GA 성과 탭 | `app.py` → `render_ga_tab()` | |
| 검색 트렌드 탭 | `app.py` → `render_trend_tab()` | |
| AI 리포트 탭 | `app.py` → `render_ai_report_tab()` | |
| 사이드바 조건 | `app.py` → `render_sidebar()` | |
| 스타일/CSS | `app.py` → `inject_styles()` | |
| 상단 KPI 카드 | `app.py` → `render_metrics()` | |

#### 절차

1. Cloud Shell에서 `nano app.py`로 해당 함수 수정
2. [공통 배포 흐름](#수정-후-배포-흐름-공통) 3~5단계 실행

#### 다른 사업군 영향

**모든 사업군에 동시 반영된다.** 앱이 1개이고 사업부는 사이드바에서 선택하는 구조이므로,
코드 변경 = 전 사업군 대시보드에 동시 적용.

> 특정 사업군에만 기능을 넣고 싶으면 코드 안에서 `if bsark == "3310":` 분기 처리.

### C. 사업군 추가

**빌드 필요: ✅**

예시: "공무원(3350)" 사업군을 추가

#### 1단계: app.py에서 BSARK_OPTIONS 수정

```bash
nano app.py
```

`BSARK_OPTIONS`를 찾아서 (파일 초반부에 있음):

```python
BSARK_OPTIONS = {
    "3310": "자격증",
    "3080": "잡",
    "3340": "한국사",
    "3350": "공무원",   # ← 이 줄 추가
}
```

#### 2단계: 빌드 & 배포

```bash
gcloud builds submit \
  --tag asia-northeast3-docker.pkg.dev/$PROJECT_ID/sales-dashboard/app:latest

gcloud run deploy sales-dashboard \
  --image=asia-northeast3-docker.pkg.dev/$PROJECT_ID/sales-dashboard/app:latest \
  --region=asia-northeast3 --platform=managed
```

#### 3단계: 사용자 권한 부여

대시보드 "사용자 관리" 탭에서:
- 해당 사업군 담당자 이메일 + 사업군 코드(`3350`) + 역할 입력 → 추가

#### 전제 조건

새 사업군의 데이터가 BigQuery에 이미 있어야 한다:
- `DASHBOARD.SALES_DAILY` 테이블에 `bsark = '3350'` 데이터가 적재되고 있어야 함
- 하나DB ETL 잡에서 해당 사업군을 포함시켜야 함

#### 다른 사업군 영향

**없음.** 사이드바에 선택지가 하나 늘어나는 것뿐.
기존 사업군 사용자는 권한이 없으면 새 사업군을 선택 자체가 안 됨.

### D. 새 탭/기능 추가

**빌드 필요: ✅**

예시: "경쟁사 분석" 탭 추가

#### 1단계: app.py에 렌더 함수 작성

```python
def render_competitor_tab(bsark: str, base_date: date) -> None:
    """경쟁사 분석 탭."""
    st.markdown("## 경쟁사 분석")
    # ... 구현
```

#### 2단계: TAB_LABELS에 추가

`main()` 함수 안의 `TAB_LABELS` 리스트에 추가:

```python
TAB_LABELS = [
    "연간", "월별", "일간", "판매상품", "환불/환급",
    "이벤트", "교재 순위", "GA 성과", "검색 트렌드", "AI 리포트",
    "경쟁사 분석",  # ← 추가
]
```

#### 3단계: 탭 렌더링 분기 추가

`main()` 함수 하단의 `elif active == ...` 체인에 추가:

```python
    elif active == "경쟁사 분석":
        render_competitor_tab(_bsark, base_date)
```

#### 4단계: 빌드 & 배포

[공통 배포 흐름](#수정-후-배포-흐름-공통) 실행.

#### 다른 사업군 영향

**모든 사업군에 새 탭이 보인다.** 특정 사업군에만 보여주고 싶으면:

```python
if _bsark in ["3310", "3080"]:
    TAB_LABELS.append("경쟁사 분석")
```

### E. SQL 쿼리 또는 테이블 변경

**빌드 필요: ✅**

예시: 새 컬럼 추가, 집계 로직 변경

#### 수정 위치

| 데이터 | 함수 |
|--------|------|
| 일별/월별 매출 | `load_sales_daily()` |
| 판매상품별 | `load_product_sales()` |
| 이벤트 | `load_event_data()` |
| 교재 순위 | `load_book_ranking()` |
| GA 트래픽 | `load_ga_traffic_monthly()` |
| GA 성과 | `load_ga_performance()` |

#### 절차

1. 해당 `load_*` 함수의 SQL 수정
2. 필요하면 렌더 함수에서 새 컬럼을 표시하도록 수정
3. 빌드 & 배포

#### 다른 사업군 영향

**같은 테이블/쿼리를 공유하므로 전 사업군에 영향.**
사업군별로 다른 쿼리가 필요하면 `if bsark == "3310":` 분기.

#### 주의

- BQ 테이블 스키마를 변경했으면(컬럼 추가 등) 기존 데이터 호환성 확인
- 뷰(View)를 사용 중이면 뷰도 같이 수정

**빌드 필요: ❌ (재배포만)**

#### GCP 콘솔에서 (GUI)

3. 컨테이너 > 변수 및 보안 비밀 > 환경변수 수정
4. 배포

#### CLI로

```bash
gcloud run deploy sales-dashboard \
  --image=asia-northeast3-docker.pkg.dev/$PROJECT_ID/sales-dashboard/app:latest \
```

#### 다른 사업군 영향

**없음.** 환경변수는 인증 설정이라 데이터/화면에 영향 없음.

## 배포 시 다른 사업군에 미치는 영향

| 변경 유형 | 영향 범위 | 이유 |
|-----------|-----------|------|
| 사용자 추가/삭제 | 해당 사용자만 | BQ 테이블 변경, 코드 무관 |
| UI 수정 (색상, 레이아웃) | **전 사업군** | 앱 1개를 공유 |
| SQL 쿼리 수정 | **전 사업군** | 같은 쿼리를 사업군 파라미터만 바꿔서 사용 |
| 사업군 추가 | 기존 사업군 무영향 | 선택지만 늘어남 |
| 새 탭 추가 | **전 사업군** (분기 처리 안 하면) | |
| 환경변수 변경 | 없음 | 인증 설정만 |
| KPI 업로드 | 해당 사업군만 | BQ 테이블 |

**핵심:** 앱이 1개이므로, 코드 변경은 전 사업군에 동시 반영된다.
특정 사업군에만 적용하고 싶으면 코드 안에서 `bsark` 분기 처리 필요.

## 롤백 방법

배포 후 문제 생기면 이전 버전으로 되돌리기:

### Cloud Run 콘솔에서 (가장 빠름)

1. [Cloud Run 콘솔](https://console.cloud.google.com/run/detail/asia-northeast3/sales-dashboard/revisions?project=ga4-bigquery-431807) > 수정본 탭
2. 이전 수정본(revision) 선택
3. "트래픽 관리" → 이전 버전에 100% 할당

```bash

gcloud run revisions list --service=sales-dashboard --region=asia-northeast3

# 이전 버전으로 트래픽 전환
gcloud run services update-traffic sales-dashboard \
  --region=asia-northeast3 \
  --to-revisions=sales-dashboard-00005-xxx=100
```

## 주의사항

1. **`$PROJECT_ID` 설정 잊지 마세요.** Cloud Shell 새로 열 때마다 초기화됨.
   ```bash
   export PROJECT_ID="ga4-bigquery-431807"
   ```

2. **`.gcloudignore` 파일이 있어야 빌드 성공함.** 없으면 `.git` 폴더 때문에 터짐.

3. **secrets.toml은 절대 git에 올리지 않기.** `.gitignore`에 포함되어 있음.

4. **배포 시 Retry 에러** — 네트워크 문제. 다시 실행하면 됨.

5. **테스트 모드 vs 프로덕션** — OAuth 동의 화면이 "테스트 중"이면 등록한 100명만 로그인 가능.
   실 서비스 시 "앱 게시" 클릭해서 프로덕션으로 전환.

6. **캐시 60초** — 사용자 추가 후 최대 1분 뒤 반영. `st.cache_data`의 `ttl=60` 때문.

7. **동시 배포 금지** — 두 사람이 동시에 다른 코드를 배포하면 하나가 덮어씀.
   수정 전에 "내가 지금 배포한다" 공유하기.
